TÀI LIỆU R-E (REVERSE ENGINEERING) THUẬT TOÁN KÝ API OKX APP
Cập nhật: 07/04/2026
Mục tiêu: Mô phỏng 100% Header Authentication của App OKX mà không cần Emulator/Frida

Trong quá trình gửi Request API, OKX Android App (phiên bản 6.166.0+) sử dụng 3 lớp bảo mật chính ở HTTP Headers nằm trong Interceptor (o.ffD class). Việc giả lập thành công các header này cho phép tạo ra số lượng lượng Bot không giới hạn thông qua Pure Python.

---
PHẦN 1: CÁC HEADER QUAN TRỌNG
1. X-Request-Timestamp: Thời gian hiện tại tính bằng milliseconds (ví dụ: 1775559606601).
2. X-Id: Giá trị băm MD5 duy nhất cho mỗi Request (1 dạng nonce chống Replay Attack).
3. X-Client-Signature: Chữ ký điện tử ECDSA sử dụng mã hóa SHA256 (CHỈ ÁP DỤNG với các API có Payload thay đổi dữ liệu như POST, PUT).
4. X-Client-Public-Key: Khóa công khai ECDSA chuẩn P-256 (SECP256R1) tương ứng với Private Key được dùng tạo X-Client-Signature.

Các Header phụ không cần ký động:
- devId: UUID của thiết bị (ví dụ: 5da582bd-cede-3d11-b09a-2ea938549b97). Phải khớp xuyên suốt qua các request.
- Authorization: Bearer JWT token (nếu yêu cầu). Lấy cố định từ Session.

---
PHẦN 2: THUẬT TOÁN TẠO X-Id (Áp dụng TẤT CẢ request)
Thuật toán: MD5 của một chuỗi nguyên mẫu (Raw String) bao gồm DevID, Request Path (Đường dẫn gốc không bao gồm Parameter) và một UUID ngẫu nhiên.

[Công thức gốc]: 
Input = "{DevId}_{Path_Không_Query}_{RandomUUID}"
X-Id = MD5(Input)

[Giải thích các biến]:
- {DevId}: Chuỗi Device ID từ App (Vd: "5da582bd-cede-3d11-b09a-2ea938549b97")
- {Path_Không_Query}: Phần Path của URL, bỏ qua mọi thứ sau dấu ?. (Ví dụ: https://www.okx.com/priapi/v5/content/ugc/publish -> Lấy "/priapi/v5/content/ugc/publish")
- {RandomUUID}: Mỗi request gửi đi sinh ra 1 UUID ngẫu nhiên (dùng thư viện uuid4)

[Mã Python minh họa]:
import hashlib
import uuid

def generate_xid(dev_id: str, url_path: str) -> str:
    # url_path VD: "/priapi/v5/rubik/public/content/feed/1"
    req_nonce = str(uuid.uuid4())
    raw_input = f"{dev_id}_{url_path}_{req_nonce}"
    return hashlib.md5(raw_input.encode('utf-8')).hexdigest()

*Lưu ý quan trọng: OKX Server không có cách nào đảo ngược thuật toán MD5 để lấy lại Random UUID. Chức năng chính của X-Id chỉ là làm "Mã Request Duy Nhất" nên server chỉ yêu cầu nó là 1 mã MD5 chuẩn và không bị trùng lặp trong thời gian ngắn là hợp lệ.

---
PHẦN 3: THUẬT TOÁN TẠO X-Client-Signature (CHỈ ÁP DỤNG POST/PUT)
Request HTTP phương thức GET không cần đến chữ ký này (hoặc trả về N/A). 
Thuật toán: Sinh chữ ký số Elliptic Curve Digital Signature Algorithm (ECDSA) dùng đường cong mã hóa SECP256R1 (NIST P-256) và được băm qua SHA256 (SHA256withECDSA).

[Công thức gốc]:
Input = "{Path_Không_Query}{RequestBody_Raw}{Timestamp}"
X-Client-Signature = BASE64_ENCODE( ECDSA_SIGN( Input, PrivateKey ) )

[Giải thích các biến]:
- {Path_Không_Query}: VD "/priapi/v5/content/ugc/publish"
- {RequestBody_Raw}: Giữ nguyên toàn bộ chuỗi ký tự JSON/Text của Body trước gửi. VD: '{"publishId":"1775559606587","content":"hh","channelId":"1001","group":"USDT"}'
- {Timestamp}: Chính là số milli-giây dùng cho chuỗi X-Request-Timestamp. (VD: "1775559606601")

*LƯU Ý RẤT QUAN TRỌNG VỀ ĐỊNH DẠNG:
Không có DẤU GẠCH DƯỚI phân cách giữa các biến. Nối thẳng vào nhau!
VD Raw String vào hàm ký sẽ là:
`/priapi/v5/content/ugc/publish{"publishId":"1775556606587","content":"h"}1775559600000`

[Giải pháp Bypass Keystore cho Bots (Pure Python)]:
Trong App Native, Private Key được bảo vệ sâu bên trong Keystore. Nhưng các API không yêu cầu phải khớp chính xác giữa Public Key và thiết bị. Backend đơn thuần đọc header X-Client-Public-Key và kiểm tra xem có khớp với chữ ký X-Client-Signature hay không.
Thay vì cần Extract Keystore, Bot Python tự generate 1 cặp Keys SECP256R1 mới:

1. Sinh cặp P-256 Keys chuẩn bị ban đầu (chỉ sinh 1 lần) ở Bot.
2. Trích xuất Public Key dạng Uncompressed (không nén), encode Base64 và nhét cứng vào header "X-Client-Public-Key".
3. Lấy Private Key tương ứng để chạy Sign cho body.
4. Convert dạng chữ ký ra DER Format rồi Base64 Encode.

[Mã Python minh họa hàm Ký]:
import ecdsa
import hashlib
import base64

def generate_signature(private_key_pem: str, method: str, url_path: str, body: str, timestamp_ms: str) -> str:
    # GET Methods usually do not need a signature
    if method.upper() == "GET":
        return None

    raw_sig_input = f"{url_path}{body}{timestamp_ms}"
    
    # Load private key từ PEM
    sk = ecdsa.SigningKey.from_pem(private_key_pem)
    
    # Ký SHA256 bằng ECDSA với output là chuẩn DER 
    signature = sk.sign(
        raw_sig_input.encode('utf-8'),
        hashfunc=hashlib.sha256,
        sigencode=ecdsa.util.sigencode_der
    )
    
    return base64.b64encode(signature).decode('utf-8')
